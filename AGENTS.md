# AGENTS.md

Read this before making changes.

## Commit message format

All commits must follow Conventional Commits so cocogitto (`cog`) can generate
the changelog. Rules:

- Use one of these types: `feat`, `fix`, `chore`, `ci`, `docs`, `refactor`,
  `style`, `test`, `perf`, `revert`, `build`, `misc`.
- The type and colon are in English; the description is in Chinese.
- Format: `<type>: <description>`, imperative mood, no trailing period.
- `feat` only for new features, `fix` only for bug fixes.
- If nothing fits, use `misc:` - it lands under "Other" in the changelog.
- No "Co-Authored-By" lines, no tool attribution, no AI mentions.

Examples:

```
feat: 添加手柄模型渲染
fix: 修复串流 UI 跟随 HMD 的问题
chore: 更新 Pico SDK 哈希
ci: 调整 release job 的 tag
docs: 完善 AGENTS.md 说明
misc: 临时提交说明
```

Install the commit-msg hook so non-conventional subjects get prefixed with
`misc:` automatically:

```bash
git config core.hooksPath .githooks
```

The hook is a safety net. Still write proper conventional commits.

## Changelog

`Changelog.md` is generated by cocogitto. Never edit it by hand.

```bash
cog changelog > Changelog.md   # regenerate from commit history
```

Release notes for each CI build are generated the same way in the GitHub
workflow, straight from the commits since the previous release tag.

## CI / releases

GitLab is the source of truth. The pipeline has three jobs:

1. `github-sync` - every push/tag to `main` is mirrored to
   `justacalico/piconeo2-wivrn` on GitHub.
2. `github-dispatch` - manual pipelines (web UI "Run pipeline", or
   `glab ci run`) push the ref and trigger the `build.yml` workflow on
   GitHub, streaming the log back into the job trace.
3. `github-release-sync` - when the build finishes, the newest GitHub
   release is copied into a same-named GitLab release backed by the package
   registry, so assets never expire.

Set `CHANNEL` to `release`, `beta`, or `alpha` when running a pipeline
manually (default `alpha`). Tags look like `v2026.09.18-r12`, or
`alpha-v...`/`beta-v...` for prerelease channels.

All jobs run on the self-hosted runner tagged `linux-truenas`.

Required GitLab CI/CD variables:

- `GITHUB_SSH_PRIVATE_KEY` (file type) - deploy key with write access on the
  GitHub mirror.
- `GH_TOKEN` (masked) - GitHub token with `repo` + `workflow` scope.

Required GitHub secrets on the mirror repo:

- `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` -
  release signing (`pico2-wivrn-release.jks`, alias `pico2-wivrn`).
- `PICO_SDK_DOWNLOAD_URL` - optional; the SDK fetch script falls back to the
  default archive.org URL.

## Signing

Release APKs are signed with `pico2-wivrn-release.jks` at the repo root.
Local builds need `keystore.properties` at the repo root (see
`src/keystore.properties.template`). Both files are gitignored - never
commit keystores, properties, or passwords anywhere.

## Versioning

`src/version.properties` holds `VERSION_CODE`/`VERSION_NAME` for local
builds. CI stamps `VERSION_CODE` with the commit count and `VERSION_NAME`
with the release tag, so published APKs always carry the tag.
